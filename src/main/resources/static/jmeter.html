Pruebas de carga con JMeter

Objetivo: medir estabilidad y tiempos de respuesta bajo distintos niveles de concurrencia.

Artefacto principal: ProyectoWeb_API_TestPlan.jmx.

Configuracion incluida en el plan:

  1. Variables globales (base_protocol, base_host, base_port, conn_timeout, resp_timeout).
  2. Escenario Smoke.
  3. Escenario de Carga.
  4. Escenario de Estres.

Procedimiento:

  1. Levantar API local en http://localhost:8080.
  2. Verificar salud con /actuator/health.
  3. Ejecutar JMeter en modo no GUI.
  4. Generar .jtl y dashboard HTML.

Comando de ejecucion usado:

"C:\Users\julio\Downloads\apache-jmeter-5.6.3\apache-jmeter-5.6.3\bin\jmeter.bat" -n -t ProyectoWeb_API_TestPlan.jmx -l run.jtl -e -o .\jmeter\results\run-report

Evidencia: run.jtl, index.html.

Evidencia JMeter

Resumen corto del "400"

No se encontraron respuestas HTTP 400 en run.jtl.

Resultados: 687 respuestas con codigo 200 y 16 errores por timeout (SocketTimeoutException).

El valor 4000 ms corresponde a una regla de tiempo maxima en el plan, no a un codigo 400 de la API.

Conclusion

JMeter permitio medir el comportamiento bajo carga y verificar que la API mantiene estabilidad en escenarios de smoke, carga y estres.
