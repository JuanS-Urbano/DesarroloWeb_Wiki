Pruebas de API con Postman

Objetivo: validar contratos HTTP, tiempos y estructura de respuestas de endpoints clave.

Entorno del proyecto: localhost - proyecto_web.

Artefactos:

  1. Coleccion: Proyecto_Web_API.postman_collection.json
  2. Environment: Proyecto_Web_Environment.postman_environment.json
  3. Guia: README.md

Procedimiento:

  1. Importar coleccion y environment en Postman Desktop.
  2. Seleccionar environment local (baseUrl=http://localhost:8080, proyecto_web).
  3. Ejecutar coleccion en Runner.
  4. Revisar tests de estado HTTP, tiempo de respuesta y estructura JSON.

Validaciones implementadas: status 200 (y 404 permitido donde aplica), tiempo maximo por request, estructura esperada de ApiResponse o error controlado.

Anexo: Configuracion y resultados JMeter

Asi quedo configurado JMeter en el proyecto:

1. Archivo principal del plan

ProyectoWeb_API_TestPlan.jmx

2. Escenarios y usuarios configurados

01 - Smoke

  • 1 usuario (hilo)
  • ramp-up: 1 segundo
  • 1 iteracion
  • endpoints: /actuator/health y /api/v1/empresas

02 - Carga

  • 30 usuarios
  • ramp-up: 60 segundos
  • 10 iteraciones por usuario
  • endpoint: /api/v1/empresas
  • think time: 200 ms

03 - Estres

  • 80 usuarios
  • ramp-up: 80 segundos
  • 5 iteraciones por usuario
  • endpoint: /actuator/health

3. Variables globales usadas

  • base_protocol = http
  • base_host = localhost
  • base_port = 8080
  • conn_timeout = 5000
  • resp_timeout = 5000

Estas variables tambien estan dentro de ProyectoWeb_API_TestPlan.jmx y explicadas en README.md.

4. Donde se guardaron los resultados

  • Archivo crudo de ejecucion: run.jtl
  • Reporte HTML para abrir en navegador: index.html
  • Carpeta completa del reporte: run-report

Resumen corto del "400"

No se encontraron respuestas HTTP 400 en run.jtl.

Resultados: 687 respuestas con codigo 200 y 16 errores por timeout (SocketTimeoutException).

El valor 4000 ms corresponde a una regla de tiempo maxima en el plan, no a un codigo 400 de la API.

Evidencia Postman

Conclusion

Las pruebas en Postman validaron los contratos de la API y permitieron comprobar respuestas, tiempos y manejo de errores esperados.
